# 能力范围与验证摘要

DuelLoop `0.1.0` 可用于开发自己的对抗决策应用。本版支持单机 Node.js 24、ESM 和 SQLite；以下“已验证”指声明范围内的工程与模拟环境检查，不是生产上线认证或策略收益保证。

## 可以使用的能力

| 能力 | 当前可用范围 | 接入者需要提供什么 |
| --- | --- | --- |
| SDK 与 CLI | 初始化应用、配置校验、决策与执行、反馈、研究、验证、激活、回退和诊断 | 应用配置、初始策略与预算 |
| Jev / pi | 官方 SDK 接入、真实 Score 决策、单模型或隔离角色会话研究 | 自己的凭据、可用模型版本与服务额度 |
| 策略更新 | Score 策略的权重、条件、问题、条件阈值与 argmax/softmax 选择；候选通过验证后激活 | 领域评价器、独立评价协议和足够证据 |
| 自定义领域 | 从公共入口实现观察、有限合法动作、执行、反馈与能力声明 | 领域规则、可恢复环境状态、执行幂等及结果查询 |
| 维护与恢复 | SQLite Schema 1、单机 worker、声明范围内的备份恢复、未知回执核对 | 环境自身的检查点与持久执行账本 |

## 不能直接当作生产能力的内容

| 内容 | 使用边界 |
| --- | --- |
| `demo/`、fixture 模型和参考模拟器 | 可以学习、集成和跑测试；fixture 不调用真实模型，内存模拟器不保存真实业务环境状态 |
| 实验脚本与受控候选 | 可以复现实验机制；受控初始缺陷与候选打法不是适用于其他领域的推荐配置 |
| Choice / Noul | Choice 提供适配器实验路径；当前策略语言只消费 Score，不能将其他问题类型直接配置成策略维度 |
| 自动研究与团队讨论 | 可以提出候选，也可能 `no_change`、被拒绝或证据不足；完成讨论不代表通过验证或获得收益 |
| 多机部署、不可信插件、真实交易与资金执行 | 本版未提供相应部署、沙箱或业务连接保证，不能仅换运行模式就视为已接入 |
| 长期稳定性与外部执行“恰好一次” | 小规模测试不能提供这些保证；外部系统必须落实幂等、状态修订检查与恢复核对 |

## 当前模型决策语义

2026-09-23 起策略 Schema 与评价协议为 `2.0`，运行时为 `duelloop-runtime-3`。每个动作都需要有效模型回答，单候选亦然；合法低置信度正常消费。模型失败保存 `stopped` 与原因并停止运行，实验也中断，不再由程序基线接管。当前实例不会因再次 `start()` 自动恢复。

本轮 `npm test` 共 147 项通过、无失败或跳过，包含低置信度正常决策、单候选模型调用、失败零执行、并发停止、迟到回答与用量、旧契约拒绝及实验吞错阻断。子进程恢复夹具现在提供完整合法的模型回答；故障恢复测试继续覆盖外部接受动作后崩溃的真实窗口。

`npm run check:package` 通过：当次 tarball 在独立目录安装，57 个公开类型以 `skipLibCheck: false` 检查通过；两个 SDK 应用完成 12 步模型策略执行，领域合规 11 项通过、2 个未提供可选场景跳过。安装包中的 SDK 文档示例完成 1 步、CLI 文档流程完成 20 步、外部领域模板完成 1 步；这些文档与模板运行阶段禁止网络。新策略/协议 Schema 接受、旧 Schema 与降级门槛拒绝也通过安装后检查。

本轮真实 Jev/pi、真实闭环及真实性能实验未执行。下面的 128 项测试、真实收益、降级率及性能数值均属于旧语义的历史验收，不能作为当前实现已验证的证据。

## 历史验证：2026-09-22 旧语义

以下为 2026-09-22 开发验收的可公开摘要。原始模型回答、最终保留样本、数据库、日志、绝对路径及机器专属摘要留在本地，不随 Git 或 npm 包分发。公开摘要保留结果和限制，不能代替使用者在自己环境中的独立验证。

| 检查 | 结果与范围 |
| --- | --- |
| 离线测试 | 128 项通过，覆盖策略、运行时、研究、存储、故障恢复及 CLI |
| 独立安装 | 当次 tarball 在干净消费项目中安装；57 个公开类型严格检查通过；12 次演示步骤完成；领域合规 11 项通过、2 个未声明可选场景未测 |
| 安装包文档与模板 | SDK 示例 1 步、CLI 文档流程 20 步、外部领域模板 1 步完成，运行阶段禁止网络 |
| 真实模型连接 | Jev Score / Choice 和 DeepSeek 经 pi 的受控工具调用通过 |
| 真实受控策略更新 | pi 自主提交候选，Jev 独立验证通过并激活；后续 20 步完成，16 个可比局面中 6 个动作分布改变 |
| 正常基线研究 | single 的 1 个会话和 team 的 3 个隔离会话均完成三个阶段；两次均为 `no_change`，无最终候选发布 |

受控更新使用 Jev `jev-1.13.0` 与 DeepSeek `deepseek-v4-pro`。初始策略故意把动作效用权重设为零；候选改变权重、条件分支和置信度阈值。最终保留实验仅执行一次：6 个独立种子块、3 类对手、每块每对手每策略 8 手，平均改善为每手 `0.2222` 净筹码，95% 区间下界约 `0.1200`。它在旧语义下验证了经验到实际策略的更新能力，不能证明正常基线、其他 bot 或真实业务的收益提升。六次先行失败、预算停止或无变化结果保留在本地；本次成功包含开发阶段的接口、预算与受控条件调整，不是未经探索的普遍效果试验。

后续 20 步含 17 次策略决策和 3 次领域降级。1 次策略决策的回答不满足旧门槛，未计入同回答对照；6 次可比变化均为 K 的 `check → bet`。新增 K 跟注分支在这 20 步中没有命中，因此不能声称该分支已有实际行为收益证据。候选门槛从 `0.10` 降为 `0.01`，效果不能全部归因于权重。

真实三路径短测每条路径 45 手，没有显示多维 Score 优于直接 Choice；示例阈值 `0.55` 下 Score 降级率约 81%。完整 SDK 的一次 30 步实测 p95 约 1.20 秒；三次小规模并发比较的 p95 比值范围为 `0.654—1.745`。这些是描述性结果，不是容量或延迟承诺。pi 费用按模型目录估算，Jev 美元价格未返回；历史缺失用量仍按未知处理。

## 自行验证与分发边界

从源码仓库执行，无需凭据：

```sh
npm ci
npm test
npm run check:package
```

真实实验的配置、调用预算和显式开关见[模型说明](models.md)。SDK / CLI 配置真实模型后会调用服务，`DUELLOOP_LIVE` 只控制仓库实验脚本，不是应用全局开关。

Git 提交包含源码、测试、脚本、空凭据配置示例和文档。安装包提供构建后的公共入口、声明文件、CLI、领域模板和文档；应用只从 `duelloop` 公共入口导入。密钥、模型原始输出、保留集记录、本机数据库、依赖目录和生成安装包均不提交。可公开的验证结果整理在本文。

项目采用 MIT；第三方依赖与远端服务的使用条件见[第三方说明](../THIRD_PARTY_NOTICES.md)。包仍为 `private: true`，尚未公开发布到 npm；远程 CI、历史生产 Schema 升级、真实业务接入和大规模长期容量测试未执行。
