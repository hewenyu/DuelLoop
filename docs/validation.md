# 能力范围与验证摘要

DuelLoop `0.2.3` 可用于开发自己的对抗决策应用。本版支持单机 Node.js 24、ESM 和 SQLite；以下“已验证”指声明范围内的工程与模拟环境检查，不是生产上线认证或策略收益保证。

## 可以使用的能力

| 能力 | 当前可用范围 | 接入者需要提供什么 |
| --- | --- | --- |
| SDK 与 CLI | 初始化应用、配置校验、决策与执行、反馈、研究、验证、激活、回退和诊断 | 应用配置、初始策略与预算 |
| Jev / pi | 官方 SDK 接入、真实 Score 决策、单模型或隔离角色会话研究 | 自己的凭据、可用模型版本与服务额度 |
| 策略更新 | Score 策略的权重、条件、问题、条件阈值与 argmax/softmax 选择；候选通过验证后激活 | 领域评价器、独立评价协议和足够证据 |
| 自定义领域 | 从公共入口实现观察、有限合法动作、执行、反馈与能力声明 | 领域规则、可恢复环境状态、执行幂等及结果查询 |
| 维护与恢复 | SQLite Schema 3（含 1/2→3 迁移）、单机 worker、声明范围内的备份恢复、未知回执核对 | 环境自身的检查点与持久执行账本 |

## 不能直接当作生产能力的内容

| 内容 | 使用边界 |
| --- | --- |
| `demo/`、fixture 模型和参考模拟器 | 可以学习、集成和跑测试；fixture 不调用真实模型，内存模拟器不保存真实业务环境状态 |
| 实验脚本与受控候选 | 可以复现实验机制；受控初始缺陷与候选打法不是适用于其他领域的推荐配置 |
| Choice / Noul | Choice 提供适配器实验路径；当前策略语言只消费 Score，不能将其他问题类型直接配置成策略维度 |
| 自动研究与团队讨论 | 可以提出候选，也可能 `no_change`、被拒绝或证据不足；完成讨论不代表通过验证或获得收益 |
| 多机部署、不可信插件、真实交易与资金执行 | 本版未提供相应部署、沙箱或业务连接保证，不能仅换运行模式就视为已接入 |
| 长期稳定性与外部执行“恰好一次” | 小规模测试不能提供这些保证；外部系统必须落实幂等、状态修订检查与恢复核对 |

## 0.2.3 bootstrap 模型维护验收

显式维护使用同一 scope 和同一 bootstrap 策略，只允许模型行为摘要变化，独立记录维护证据和审计，不创建研究验证。新增离线回归覆盖旧发布和轨迹 pin 保留、新轨迹使用新发布、停止与排空要求、非模型依赖变更拒绝、坏证据和过期基线拒绝、研究与未决动作拒绝、禁止伪造 maintenance 来源，以及审计写入故障后的原子回滚。数据库重开后使用新的行为依赖完成 fixture 决策并创建研究任务，未调用真实 provider。

`npm test` 全量通过；`npm run check:package` 独立安装通过，严格检查 62 个公共类型、12 步 SDK 演示、11 项领域合规（2 项可选场景跳过），并在禁网阶段运行安装包文档和 CLI 示例。维护报告是宿主实际验证结果的声明；这些离线检查不构成策略收益或生产环境验收。

逐调用取消和独立模型截止时间、提前轨迹 pin、只读 pin 查询、稳定回执事件去重和首次结算触发，见 [契约设计](live-decision-contracts.md)。SQLite Schema 3 从 Schema 1/2 原子迁移，runtime 5 拒绝沿用旧行为绑定。旧反馈修订继续进入快照，取消任务的迟到结果只追加诊断和费用记录。

本轮 `npm test` 通过 239 项离线测试；`npm run check:package` 独立安装通过，严格检查 60 个公共类型、12 步 SDK 演示及 11 项领域合规（2 项未提供的可选场景跳过），安装包文档与 CLI 示例在禁网运行阶段通过。未调用收费模型，未宣称真实环境收益。测试包括同时运行的 stream 取消隔离、provider 取消、模型/权限双截止、回执重复及冲突、终态后旧事件重放、轨迹激活/恢复、旧库迁移与首次结算触发。冷恢复测试另外覆盖实际子进程 SIGKILL、clean close、活 owner 与跨 hostname 拒绝、原 intent 幂等恢复、取消和过期权限；恢复不调用模型、不创建新 intent。新增 scopeSummary 测试在另一连接持有写事务时仍能读取，跳过损坏的历史 release/eligibility 诊断，并观察其他连接提交的激活、模式和暂停更新。原始 0.2.1 验证保留在下方，不追溯改写。

## 0.2.0 工程验收记录

策略 Schema 为 `2.0`，评价协议为 `3.0`，运行时为 `duelloop-runtime-4`。每个动作都需要有效模型回答，单候选亦然；合法低置信度正常消费。模型失败保存 `stopped` 与原因并停止运行，实验也中断。再次 `start()` 不能清除失败。

本轮修复发布延期、恢复资格、模型行为绑定、嵌入调用排空、历史增长查询、快照写锁和保留集资源等待。研究产出与激活分开，模型、存储或执行故障不会通过程序代打掩盖。具体接口、迁移要求和配置变化见[工程化修复](engineering-reliability.md)。

`npm test` 的 184 项离线测试全部通过，0 失败、0 跳过；独立安装检查通过。测试覆盖同名 fixture→real 恢复、验证撤销竞态、激活延期继续轮询、单次反馈触发、直接请求取消与排空、忽略取消的适配器、并发数据库迁移、保留集更名/额度绕过拒绝，以及子进程崩溃后的真实执行核对窗口。

`npm run check:package` 使用当次 `0.2.0` tarball 在独立目录安装：57 个公开类型以 `skipLibCheck: false` 检查通过；两个 SDK 应用完成 12 步，领域合规 11 项通过、2 个未提供可选场景跳过。安装包 SDK 文档示例完成 1 步、CLI 文档流程完成 20 步、外部领域模板完成 1 步；文档与模板运行阶段禁止网络。协议 3.0 和旧契约拒绝也经过安装后检查。

### 历史规模与快慢并发

macOS arm64、Apple M4、Node.js 24.13.0，本地磁盘 SQLite WAL。每个档位分别独立/并发运行两次，每次预热 10 步、测量 300 步；交替测量顺序，使用全新数据库。每条合成历史包含决策、已完成意图和反馈，100000 档位不是只有空日志。并发慢 worker 同时创建各 1000 条记录的快照并运行完整轨迹开发评估。没有调用付费模型或消耗最终保留集。

| 历史记录组数 | 独立完整 step P95（ms） | 并发完整 step P95（ms） | 并发完整 step P99（ms） |
| --- | --- | --- | --- |
| 1000 | 2.45—2.51 | 2.91—3.07 | 11.61—11.93 |
| 10000 | 2.61—2.64 | 2.89—2.94 | 11.09—11.49 |
| 100000 | 2.82—2.96 | 4.95—5.96 | 11.87—12.18 |

上表为两次重复的观测范围，不是置信区间。共 3600 步全部完成，慢 worker 完成 30 次开发评估；1800 个并发步骤均与快照/评估区间重叠，超时、停止和 5000ms 截止超出率均为 0。规模变大后仍存在额外 I/O 与同库写锁开销，不能据此承诺更短业务时限或多机容量。

100000 档位初始数据库约 1288.6 MiB；快 worker 采样峰值堆内存在各档位为 68.3—74.4 MiB，慢 worker 为 156.9—214.9 MiB；快照为 5.10—5.18 MiB，没有随全部历史复制增长。快 worker 单次写锁获取耗时最大约 20.90 ms。这些是本次样本结果，采样可能错过瞬时峰值。

实验分别记录 `modelLatencyMs`、`decisionEndToEndLatencyMs`、`executionAckLatencyMs` 和外层完整 `stepLatencyMs`。SQLite 指标测量 `BEGIN IMMEDIATE` 获取耗时（包含语句开销）；内存记录每个 worker 的堆和整个进程共享 RSS。详细原始样本保存在本地，不进入公开安装包；脚本 [history-benchmark.mjs](https://github.com/hewenyu/DuelLoop/blob/master/scripts/history-benchmark.mjs) 可重跑相同规格。

这轮真实 Jev/pi、真实闭环与策略收益消融实验未执行。可以开始真实项目的领域适配、SDK 集成、仿真和受控运行开发；真实环境的幂等、恢复能力、模型表现和业务时限仍须在该项目验证。下述真实收益、降级率与服务性能属于旧语义历史，不能作为当前模型效果证据。

受控更新使用 Jev `jev-1.13.0` 与 DeepSeek `deepseek-v4-pro`。初始策略故意把动作效用权重设为零；候选改变权重、条件分支和置信度阈值。最终保留实验仅执行一次：6 个独立种子块、3 类对手、每块每对手每策略 8 手，平均改善为每手 `0.2222` 净筹码，95% 区间下界约 `0.1200`。它在旧语义下验证了经验到实际策略的更新能力，不能证明正常基线、其他 bot 或真实业务的收益提升。六次先行失败、预算停止或无变化结果保留在本地；本次成功包含开发阶段的接口、预算与受控条件调整，不是未经探索的普遍效果试验。

后续 20 步含 17 次策略决策和 3 次领域降级。1 次策略决策的回答不满足旧门槛，未计入同回答对照；6 次可比变化均为 K 的 `check → bet`。新增 K 跟注分支在这 20 步中没有命中，因此不能声称该分支已有实际行为收益证据。候选门槛从 `0.10` 降为 `0.01`，效果不能全部归因于权重。

真实三路径短测每条路径 45 手，没有显示多维 Score 优于直接 Choice；示例阈值 `0.55` 下 Score 降级率约 81%。完整 SDK 的一次 30 步实测 p95 约 1.20 秒；三次小规模并发比较的 p95 比值范围为 `0.654—1.745`。这些是描述性结果，不是容量或延迟承诺。pi 费用按模型目录估算，Jev 美元价格未返回；历史缺失用量仍按未知处理。

## 自行验证与分发边界

从源码仓库执行，无需凭据：

```sh
npm ci
npm test
npm run check:package
```

真实实验的配置、调用预算和显式开关见[模型说明](models.md)。SDK / CLI 配置真实模型后会调用服务，`DUELLOOP_LIVE` 只控制仓库实验脚本，不是应用全局开关。

Git 提交包含源码、测试、脚本、空凭据配置示例和文档。安装包提供构建后的公共入口、声明文件、CLI、领域模板和文档；应用只从 `duelloop` 公共入口导入。密钥、模型原始输出、保留集记录、本机数据库、依赖目录和生成安装包均不提交。可公开的验证结果整理在本文。

项目采用 MIT；第三方依赖与远端服务的使用条件见[第三方说明](../THIRD_PARTY_NOTICES.md)。包仍为 `private: true`，尚未公开发布到 npm；历史生产 Schema 升级、真实业务接入和大规模长期容量测试未执行。
