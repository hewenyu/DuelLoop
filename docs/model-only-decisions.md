# DuelLoop 迭代设计：模型决策，失败停止

当前工程契约以 [0.2.0 持续运行修复](engineering-reliability.md)、[0.2.1 SDK 接入](sdk.md)和[验证记录](validation.md)为准；下文保留设计与历史实施上下文。

日期：2026-09-23。状态：已实现，验证记录见文末。本轮修正此前设计中的领域降级与强制动作路径。本文的行为约定优先于旧设计和历史实验中关于降级的描述。

## 产品目标与本轮范围

DuelLoop 是面向对抗决策应用的开发者框架：使用者安装 SDK、接入自己的环境、配置模型和策略，开发、运行和维护自己的应用。快循环由 Jev 基于当前可执行策略做决策；慢循环由 pi 驱动 LLM 复盘，提出候选，经独立验证后替换后续实际使用的策略。

本轮完成一项贯穿全框架的行为修正：取消程序接管模型决策的路径。模型不可用时宁可停止，不通过预设打法、候选排序或领域基线继续行动。程序仍负责规则计算、合法候选生成、模型答案校验、策略组合、执行和持久化。

mu 源码研究提出的条件化研究记忆、结构化研究工作区、争议实验和阶段恢复保留为后续方向；本轮先统一真实执行、研究实验、示例和文档的模型决策语义，不引入新的通用 Agent 平台。

## 行为契约

| 情形 | 框架行为 |
| --- | --- |
| 模型返回完整、合法的回答 | 按绑定策略消费模型回答并形成动作 |
| 回答的 confidence 很低，包括 0 | 记录该值，正常消费回答；不设接受门槛，不替换动作 |
| 只有一个合法候选 | 仍调用决策模型并验证回答，成功后才能执行 |
| 没有合法候选 | 停止当前运行并明确记录原因，不自行选择等待、弃牌或其他动作 |
| 模型超时、连接失败、答案缺失或格式/数值非法 | 保存可获得的失败记录与用量，抛出错误，停止快循环，不创建执行意图 |
| 模型版本不符、观察过期或合法性校验失败 | 拒绝决策或执行并向调用者报告错误，不重新选动作 |
| 研究模型失败、证据不足或未找到改进 | 保留当前已验证策略；不伪造候选、不切换到程序打法。快循环模型健康时可以继续运行 |
| 实验中决策模型失败 | 中断本次实验，不使用程序动作补齐轨迹，不凭部分成功样本发布策略 |

confidence 的类型与范围校验仍保留；这属于模型接口契约，不是置信度门槛。策略的收益权重、条件分支和 argmax/softmax 组合继续有效，且每个可执行动作都必须基于本次有效模型回答。

## SDK 与策略契约调整

1. `StrategyPackage.schemaVersion` 升为 `2.0`，删除 `decision.minRequiredConfidence`、`fallback` 和原本指向领域基线的 `exitConditions`。旧字段与旧 Schema 明确拒绝，不静默忽略。
2. `DomainDefinition` 删除 `fallback()` 和 `baselineVersion`；`BehaviorDependencies` 删除 `fallbackBaseline`。领域提供可见观察、合法候选、执行与反馈，不提供模型失败后的接管算法。
3. `DecisionRecord.decisionSource` 仅为 `strategy` 或 `stopped`。停止记录没有动作，以 `stopReason` 保存机器可读原因；已知模型回答、版本、费用和原策略摘要保留。SDK 抛出的错误关联决策 ID，调用方可以查询记录。
4. 模型失败使当前运行实例进入停止状态；再次调用 `start()` 不自动清除该失败。宿主应修复原因、核对已有外部执行并显式重新创建运行实例。实例停止不承诺撤销已经发送给外部环境的其他在途动作。
5. 执行入口拒绝停止记录和旧的非模型动作来源。单候选路径与多候选路径执行同一套模型、持久化和新鲜度检查。
6. 运行时行为版本升级，旧发布与旧验证不得继承新语义下的运行资格。数据库结构无需因删除 JSON 契约字段而改写；历史产物保留，旧活动发布需要使用新策略和新验证重新绑定。

## 研究与验证

研究工具的候选 Schema、语言说明、差异检查和行为夹具同步删除兜底配置。LLM 不得提出以降低接受门槛或切换程序基线为手段的候选。

`EvaluationProtocol.version` 升为 `2.0`，删除 `maxFallbackRate`；评价片段和报告删除 `fallbacks`、`fallbackRate`。模型失败产生实验错误或不确定结论，不产生成功的代打样本。旧策略作为候选对照时，必须同样调用决策模型；“对照策略”不再指程序兜底。

开发与最终保留评估隔离、模型调用预算、反馈修订、知识状态隔离、策略激活边界保持原有机制。不得为了消除旧结果中的失败而重置实验数据库或保留集使用额度。

## 示例、测试与迁移

离线 fixture 是使用者显式选择的测试模型，不能在真实模型失败后自动启用。领域合规测试可显式构造沙箱命令检查适配器接口，不能把测试动作选择器暴露为生产兜底。

M0 改为比较 Jev Choice 与 Jev Score 两条模型路径，移除程序基线路径。基准、真实实验脚本、SDK 演示和领域模板统一使用新契约。历史真实实验如实保留，并明确其结果属于旧行为，不能证明本轮实现或新策略效果。

本轮不自动调用收费模型，不提交或推送代码，不发布 npm 包。交付当前工作区的可审查实现、离线验证与独立安装验证结果。

## 验收标准

- 低置信度但合法的模型回答正常产生模型策略动作，不触发任何替代选择。
- 单候选成功与失败都证明实际调用了决策模型；失败不执行该候选。
- 超时、不可达、缺失、非法与版本不符回答都不会调用领域执行接口或创建新执行意图。
- 停止原因和已知用量可查询；同一实例不因再次启动而自动恢复。
- 多流情况下，模型失败后尚未发送的动作被停止状态阻止；宿主执行与影子模式遵守同样的来源限制。
- 旧 Schema、置信度门槛与兜底字段明确拒绝；旧发布绑定不能静默兼容。
- 评价器失败不能通过兜底、吞错或丢弃失败样本获得通过；研究仍允许 `no_change`。
- 项目离线测试、构建、独立 tarball 安装及公开示例检查通过；真实模型验收若未执行则明确标注。

## 实施记录

- 运行时、策略 Schema、研究候选工具、评价协议、CLI、参考领域和 SDK 示例已统一为上述契约。旧策略与评价协议明确拒绝，运行时行为版本为 `duelloop-runtime-3`。
- 模型失败记录 `stopped` 并抛错，实例不会自动重新启动。有效 confidence=0 仍消费，单候选也必须完成模型调用。并发停止在实际发送前再次检查；未发送意图记为 `rejected`，已发送而结果不明的意图保持 `unknown`。
- 可获得的迟到用量以 `decision.late_model_result` 追加事件保存，不修改原停止记录、不恢复动作。宿主已关闭存储时无法保证追加此事件。
- 第三方评价器即使吞掉模型异常，也无法用本次实验取得通过；未完成模型调用、旧策略和虚报真实调用数会被拒绝。
- `npm test`：147 项通过，0 失败、0 跳过；包含故障、并发、进程恢复、研究与 CLI 回归。
- 独立安装检查通过：57 个公开类型、12 步 SDK 演示、11 项领域合规检查，2 个未提供可选场景跳过；安装包文档 SDK 1 步、CLI 20 步、外部领域模板 1 步均通过。新 Schema 与旧字段拒绝在安装后再次验证；详细范围见[验证摘要](validation.md)。
- 未调用收费模型；旧真实实验和数据库保持原样，不作为本轮效果验证。
